# A digital storefront that demonstrates the product

**Why (Tony):** "something that feels like a web solution for the future AI economy" and a
platform that builds and showcases digital products. Functionality now reaches publication;
the visitor's first impression still reads as a plain card above a legacy business template.

## Observed in the local browser at295ec50

001d succeeds at draft/save/review/local publish, separate saved version2 versus live version1,
and Use reaches the actual document-to-data workspace. But the page starts with a small h2
profile card; the business h1 and repeated headline come below it, with another repeated
availability badge. Beside the main title is an empty card saying `Use a product above. Nothing
else is open to book here.` The picker says Untitled product for a released Invoice reader.
The content is useful but its hierarchy still feels appended to the old class page.

## Bounded implementation

1. Design first. One coherent digital business header: identity, strong promise, audience,
   founder attribution, honest availability and clear primary action. Follow with product
   demonstration/capabilities and supported products. No duplicated title/status, empty booking
   placeholder, zero-follower filler or unrelated acquisition terms on a customer page. Preserve
   deliberate separately shared numbers and a valid legacy offering on mixed businesses.
2. A distinctive code-native product example, not decoration. Extend the owner-edited public
   draft/review schema with an optional bounded illustrative example tied to a featured product:
   owner-authored fictional sample input and a small set of plain-text expected output fields.
   Label it an example, not a live run. Useful controls switch input/result views and actually
   work. Keep the actual `Use this product` route distinct. No fake running animation or invented
   provider validation. Missing example gets a well-designed honest state, not fabricated data.
3. All example content is deliberate public metadata, saved/reviewed/published under001d1's
   exact snapshot rules. Never import customer documents/results, private prompts, drafts,
   evaluation fixtures, source/provider settings or artifact internals automatically. Give
   concise authoring guidance to use fictional content. Text-only bounded allowlist; no arbitrary
   HTML, iframe, external image or executable code. Allow replacing/removing the example.
4. Make the public profile/editor and discovery cards share the live headline, kind and honest
   product availability. Improve useful card structure with a small example/capability preview
   only when explicitly published. No fake stats. Keep acquisition discovery separate and
   preserve stable business URLs. The profile editor should offer a direct View live page link
   when published and make saved/live versions visually understandable.
5. Use the established ink/mint/neutral tokens and consistent type/icon system. Desktop1440/
   1280 and mobile390 layouts, visible keyboard focus, accessible example controls, reduced
   motion and long text. The result should be a purposeful product surface, not a stack of
   equally weighted cards. No network/billing/production capability claims from local fixtures.

## Done when

One founder creates a fictional example, saves/reviews/publishes it locally; a visitor discovers
the exact published product, understands the example, switches input/output, and opens the real
customer workspace. Subsequent draft edits stay private; removing example then publishing
removes it publicly; unpublish/retire retain existing customer rights. Legacy, mixed, coming-soon,
multiple products, long text and no-example states remain usable. Narrow public API tests for
bounds/canary privacy/snapshot and withdrawal; meaningful interaction checks where available.
Extend the isolated publication preview with the new states and record exact commands/actors.
npm check/webbuild; local commits and report, then stop for Astra review. No milestone claim.

P1/L after001d1. This is product functionality and presentation, not external publication. No
push/release/submission, signing/deployment, live provider/RPC/wallet/main wiring, new spending,
research access/assessment or Day One. Preserve all six milestones including import/network/M6.
