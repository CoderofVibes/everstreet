# Reconcile showcase design before building it

P1/M for design/data contract, then staged implementation under the existing plan. Open, not
dispatched. Astra's ten decisions and proposed order are in IndependentBuildAssessment.

## Experience and layers

The base platform works for every owner. Public sample/Follow it screens teach one coherent
business story without writing commerce history. A separate fictional demo account fills the
real dashboard using flows on the simulated chain. Keep all three layers explicit.

## Required corrections to Fable's proposal

1. Derive all balances/history from real flows: 350 purchased minus 212 charged is 138, not149;
   returned holds are not new prepaid units. Reconcile day-by-day counts and 49-agent-use claim.
   Fix the sample invoice mismatch (200+60 versus the other example's294).
2. Per-source provenance: chain, provider, builds, history, observations and fees independently
   identify simulation/testnet/unknown. No global label flip; no fabricated historical chain time.
3. Public examples use an allowlisted demo-only projection, never owner endpoints with fields
   merely hidden in the browser. Deny private identities/notes/records. Public interactive demo
   sessions need isolation, bounded resets and synthetic outbound adapters. No shared real keys
   or credentials committed in a seed. Persistence/analytics must match "nothing recorded".
4. Early small Ledgerline history and projection unlock step2; the full three-business seed and
   dashboard stay later. Do not create a dependency on unbuilt Relaydesk/Signalwatch engines.
5. Correct actor-specific attention: buyer acceptance belongs to buyer; customer agent renewal
   belongs to customer; completed requests cannot remain stuck in final history.
6. Implement Astra's answers: Operate owns portfolio, separate genuine catalog, semantic chart
   patterns, aggregate customer data, component illustrations, fictional initials, named
   disclosures, stable release sequence/digest. Founder name is provisional for Tony.

## Validation and cuts

Write one fixture-derived numeric specification and test each headline against it. Every chart
has units, provenance and an accessible table; don't create hundreds of keyboard tab stops.
Use standalone revenue and compute charts, no conversions. Unknown costs stay unknown.
Test public projection isolation and sample no-write behavior. Full width/phone/keyboard/zoom
pass on each stage before adding more panels. Cut decorative secondary charts first; approved
families/team work require Tony's scope decision, not silent removal.

Design correction does not authorize publishing, hosting, live inference, testnet deployment,
worker dispatch or a public demo account. Worker-backed real releases stay disabled.
