# Preserve the studio conversation across panel switches

**Why (Tony's words):** "A good solution for building within a platform that will then showcase their product."

## What the person sees and does

The founder can switch Assistant → Brief → Assistant without losing an unsent thought or
an unresolved request. This is independently reproduced after 002b1; see
`../reports/2026-11-02_002b-panel-review.md`. Keep editor navigation fluid and protect work.

## Underneath

ConversationPanel currently unmounts when the side panel changes. Preserve conversation
composer/outbox at the studio's actor/project/owner-epoch scope, or keep the component alive
with correct hidden/focus/poll behavior. Reset on person/project/ownership changes. Preserve
the immutable text/key pair and resolution of an in-flight send while hidden; never create
a duplicate on return. The existing newKey, outbox and load-order safeguards must survive.

Do not broaden persistence to other people. Browser-refresh recovery is a separately stated
behavior; if implementing it, use explicit scoped versioned storage and truthful UI. The
minimal correction can keep state only for the lifetime of the current studio.

## Done when

1. Type an unsent thought; visit Brief and Screens; return and see it unchanged.
2. Send through a delayed response; change panels before the response; return to one accepted
   request with typed-ahead text preserved. Unknown responses keep the same retry identity.
3. Change actor or project; no earlier person's composer/outbox appears.
4. Existing proposal application, latest/older history paging and keyboard focus still work.

Run npm run check and npm run web:build on stable code. Report observed evidence and limits.
Astra performs independent browser review. Leave milestone 002 open.
