# Consolidated candidate: remaining review boundary

Read-only Claude completed `2026-11-02_003d-consolidated-candidate.md`. This is a candidate,
not accepted contract work. Pending beneficiary references now protect the lifetime of claim
slots; hold/slot identity is consolidated; the last closed hold includes a used bitmap;
close attempts have intent/signed/sent states. Those address the preceding design omissions.
No implementation, test execution, gas measurement or live-chain evidence occurred.

One further safety/liveness boundary needs explicit treatment before the full managed-close
design is accepted: **restoring the runtime restores customer/release state too**. The current
proof quarantines administration and re-drains restored admin operations, while asserting
that customer paths are unaffected. A backup can contain an older active release, missing
delivered invocation rows, or older model/config identities. A previously signed close may
still land while the restarted runtime has that older service state. Merely fencing new
admin commits does not prove the service manifest actually served to customers is current.

Specify recovery for immutable artifacts, active release selection and invocation/outbox
records against their durable authority. Reconcile uncertain previously dispatched customer
calls without repeating paid work; an absent local row must not mean a request was never
served. Where recovery cannot establish those facts, disclose temporary service unavailability
and preserve entitlements rather than claiming uninterrupted or duplicate-free processing.
Include a backup taken before a release and before a delivered invocation, restored while a
signed close is in flight. This is a design counterexample to examine, not an executed test.

Also distinguish a permanently unavailable charge outcome from a batch that may safely allow
the next hold. Retention requires resolved batches and G2 blocks the next hold until resolution;
an archival RPC outage must have a named visible state and recovery path rather than an
implicit permanent lock or guessed "uncharged" result. The contract's bounded storage and
the gateway's stronger history guarantees must be stated separately.

The narrow entitlement/storage/claims core can be specified and unit-tested independently,
but authorizing that slice would not accept the managed-close or runtime-restore guarantees.
Astra should scope any later implementation job accordingly after primary-source review.
