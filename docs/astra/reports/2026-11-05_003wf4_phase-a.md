## The design in short (see the document for the exact contracts)

- **Contract (source only, no deployment):**
  - `get_plan_terms()`: version, guarded, `next_plan_id`, cap, a measured `plan_bytes`, byte
    cost, control and generation, live deal, rules.
  - `create_plan_guarded(input, expected_control_seq, expected_plan_id)`: atomic `E_REVIEWED` and
    `E_REVIEWED_PLAN` refusals, with the existing rules.
  - The quote is the measured bytes × byte cost, with the excess refunded. A stale quote refuses
    `E_STORAGE` with nothing created.
- **Wallet request:** a new SaleActions kind, `create_plan`, with the existing durable protocol:
  - one pinned review, one row per exclusivity identity, durable before the ask;
  - checked by its own transaction only;
  - confirmed only with the returned id, the full `get_plan` readback equal to the reviewed input,
    and `created_generation`;
  - never a duplicate offered as recovery;
  - the draft kept apart from the unresolved request;
  - away-and-back evidence scoped to the participant.
- **Timing: one `servePolicy`**, from the configuration at each read, used by guided creation,
  inspection, offer creation, customer prepare and readiness. It answers Astra's 04:5x
  reproductions, including the default plan's late-authorization case:
  - `reserve = max(MIN_SERVE_MS, timeoutMs + executionMarginMs)`;
  - `signWithin = window − reserve − submitMarginMs` must be at least 60 s (minimum usable hold
    300 s with defaults);
  - **`sign_by` and `accept_by` now reserve execution time**, so a signature at the latest
    permitted moment still runs;
  - settlement grace ≥ `deliveryTimeoutMs + submitMarginMs`;
  - an unusable plan stays inspectable, offer creation refuses it (`plan_unusable`), and an
    existing offer is shown unavailable after a configuration change;
  - regressions for every reproduced boundary, the late-but-permitted path, and two non-default
    configurations.
- **Operator mask:**
  - the review shows the current slot and the exact resulting mask;
  - an existing SUPPORT is kept by default (METERING|SUPPORT) and removed only by an explicit,
    reviewed choice;
  - confirmation says permission, not service readiness (that stays the separate D4 reading).
- **Offer:** the confirmed plan feeds the existing independent offer review; it is never skipped.
- **Acceptance matrix:**
  - C-1..5 (Rust); M-1..2 (TS double); S-1..8 (services);
  - P-1..3 (actual processes, including the normal-route founder plan → grant → offer → customer
    use);
  - B-1..2 (browser, desktop and 390, keyboard and recovery).

  Each is tied to its evidence layer, with budgets stated.
