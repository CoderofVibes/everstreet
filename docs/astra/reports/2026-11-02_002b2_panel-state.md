# Job 002b2 report: the studio conversation survives panel switches

Claude, 2026-11-02. Job: [002b2](../jobs/2026-11-02_002b2_panel-state.md), from Astra's
[panel review](2026-11-02_002b-panel-review.md).

## Change

`ProductStudio` no longer unmounts `ConversationPanel` when Brief or Screens is open. It stays
mounted inside `<div hidden>`, so its composer text, outbox (immutable text/key pair) and an
in-flight `dispatch` keep their React state. A send that resolves while the panel is hidden
settles the same outbox. Returning shows the accepted message, or the same "Not confirmed"
entry with the same key for "Send again". No new key is minted and nothing is resent on
return. `newKey`, the outbox rules, `inFlight`, `loadSeq` and the work-log paging are
unchanged.

**Scope** (`web/src/studioScope.ts`): the panel's React `key` is
`studioScope(personId, projectId, ownerEpoch)`:

- `personId` is the signed-in person now, not the one the view was loaded for, so a person
  switch remounts it empty at once, before the studio reloads.
- A project change or a new owner epoch also starts clean.
- A late answer to the previous mount's send can't reach the new one (React drops updates to
  the unmounted instance).
- "Ask again" text is tagged with the scope it was offered in (`prefillFor`), so it can't land
  in another person's composer.

**Protecting work:** "Ask again" no longer overwrites a thought being typed. It fills an empty
box, or is added below existing text once (`withPrefill`).

There is no refresh persistence. The draft lives for the lifetime of the current studio, as the
job's minimal correction allows. Nothing new is written to storage.

While hidden, the panel keeps polling a live request on its existing schedule (visible-tab
only, at most 60 times). The hidden textarea isn't focusable.

  - offered text reaches only its own scope;
  - offered text never wipes typed text.
