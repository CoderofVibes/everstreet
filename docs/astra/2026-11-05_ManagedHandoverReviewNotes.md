## Boundaries the design and tests must cover

1. **Completed invocation is not completed delivery.** In server/src/invocations.ts, ManagedRuntime.run commits finish(completed) before awaiting the customer sink. CustomerUses.keepResult protects and records the result afterward. A drain query checking only runtime_invocations.state != running can therefore miss in-flight protected result publication. Hold the sink/protection write at a deterministic barrier; prove the handover preserves the same customer result, reference and entitlement, with no orphan/late callback escaping its documented policy.
2. **Admission after asynchronous reads.** CustomerUses.execute awaits protected input load and fresh chain views before startCustomer's transaction. Its current inTx callback rechecks request/settlement/offer/release/binding/time/local epoch. Add the business-gate check at that atomic admission boundary; a pre-read HTTP check alone leaves a gap. Test a request paused before inTx while the coordinator acquires its gate.
3. **More than one evaluation invocation.** Evaluations.execute iterates cases, checking runner ownership and invoking runtime.start each time. The handover must account for the durable eval run and prevent a live old-owner loop from starting its next case after readiness, even if no individual invocation is momentarily running. Test between cases, not only while the provider awaits.
4. **Build claim and dispatch are different points.** BuildWorker.claim, guarded lease writes and the dispatch transaction are distinct. A claimed worker can wait before provider.start; a lease expiry or abort signal does not establish that an external call never ran. Prove gate coverage at claim, dispatch, final artifact publication and stale-owner fencing. Retain unknown usage honestly.
5. **Synchronous owner mutations need a durable check.** Releases.activate/rollback use Store transactions and local owner epoch. New gate invariants must be checked inside the write transaction, as must other owner mutations found by the complete inventory. A pre-handler read in one process cannot protect a second process's subsequent commit.
6. **Separate local ownership epoch from chain generation.** Store.controlEpoch derives local ownership-row count. CloseOrder.expected_generation is the contract generation. Preserve explicit binding and verify both rather than assuming their numeric equality (including initial import/reconciliation).
7. **Do not confuse a transport deadline with terminal work.** Runtime and build adapters use cancellation/timeout machinery, while costs may remain unknown and result persistence can be later. Specify what unresolved work blocks close, what can safely remain journaled, and why. Do not call an expired peer lease proof of no external side effect.
8. **Gate release requires exact terminal sale evidence.** close_sale and abort_close enforce contract identity/time; app-wide compose admission/drain proves only shutdown behavior. Neither supplies a per-business multi-process fence. Review behavior if an original close is submitted with no reply, the coordinator lease changes, abort races, or the local reconciliation fails after the chain close. No reopening stale seller writes from a local timeout.

These points sharpen existing003wf3 requirements; they add no external scope and do not remove the customer/build/release/process/browser acceptance matrix. Pending customer browser permissions and all six milestones remain open.

### Required design corrections before implementation

**D1 — terminal outcome and current authority are separate facts.** A historical aborted outcome alone cannot reopen a business under an assumed seller. Before released_to_seller, verify the current chain control and relevant local epoch still correspond to that seller, and account for any newer live Closing deal. A stale/late pinned read cannot clear a newer gate. Likewise, V3Intents result superseded is NOT evidence that this handover's buyer currently operates or that its service grants hold. Do not group superseded with applied/already as successful buyer readiness. Handle it through explicit current-authority reconciliation/attention without restoring historical authority. Include deterministic stale-read/newer-deal/away-and-back cases; use existing observation ordering rather than freshness alone.

**D2 — finite logs must remain recoverable for a long close.** The design allows a24-hour window, a10-second pass and only64 evidence rows/256 journal rows. Recording every repeated readiness failure exhausts that in minutes. Specify bounded current diagnostics/coalescing and reserve immutable capacity for dispatch and terminal evidence. Reaching a diagnostic limit must not prevent reading the exact outcome, applying it once, opening the right gate or recording an abort/claim. Test with a deliberately tiny cap and many unchanged passes before final close/abort. Preserve meaningful immutable transition evidence without unbounded growth.

**D3 — deployment compatibility is an operational prerequisite, not a row-count proof.** An old process can remain alive or start after a single marker/presence check; old code does not know a new gate exists. Define versioned process capabilities and startup/coordination checks, plus the explicit requirement to quiesce incompatible processes before enabling the feature. Test an incompatible live peer, a peer appearing after initial validation, and an unavailable/stale peer according to the documented guarantee. Do not claim an arbitrary old binary sharing writable SQLite is prevented from writing solely by a schema marker. The source change can reject unsupported operation; no host/administrative setup is authorized here.

**D4 — ready to administer differs from ready to serve.** Reconciliation may legitimately make the buyer owner while runtime/provider/release/offer/budget/metering capability is unavailable. Do not label Customers served from gate-open+meter alone. Read the existing actual readiness checks and show precise unavailable/paused reasons. Missing capability must not strand the new owner behind a gate that prevents fixing it. Verify restart with changed provider configuration or unavailable runtime, as well as the normal customer-use-after-close scenario.

**D5 — service inventory must include app-check workers and conversations.** The table lists app checks and conversations but readiness defines only eval_runs/runtime invocations. Explicitly classify already-running app checks, studio conversations, preview issuance and their late publication/cost effects; prove their fence or drain with actual worker/service barriers. Do not infer that gating their start proves already-running work safe. Existing isolated-worker/live-execution gates remain unchanged; synthetic barrier tests can establish coordination behavior only.

**D6 — caller-visible pause facts must be exact.** Execute may encounter a unit already reserved; saying “nothing was held” for every handover_pause response is wrong in that case. Tailor the message to the request: new admission refused versus existing reserved unit being returned versus unknown settlement. Derive the UI from actual state and keep original request identity/history; no charge/return claim before proof.

Phase-B test inventory must include these cases alongside every existing C/M/S/P/B item. Implement boundedly, commit coherent checkpoints, run appropriate focused checks then required fullcheck/webbuild/Rust checks, and report exact evidence. Keep full child/parent scope; a partial implementation remains partial. Astra will inspect code and actual UI independently. All existing permissions and research/worker/external limits remain.

D7 — lease validity includes expiry, not just generation. Coordinator mutations must check holder, generation AND unexpired lease at the transaction boundary. A CAS on business_id+gen alone does not reject a late expired holder before another holder claims. Add that precise no-takeover-yet case, alongside takeover and original-order recovery. Transaction broadcasts already durably admitted can still finish; their evidence must be reconciled rather than mislabeled absent.
